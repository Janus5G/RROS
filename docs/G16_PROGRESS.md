## Implemented (separately versioned v1 adapters, `kernel/compat_registry.c`)

- `chromaneural-identity`: verifies the nodeId/public-key binding (strict canonical base64, lowercase hex).
- `chromaneural-cnrb`: CNRB v1 pack/unpack with HMAC-SHA256, strict canonical metadata, 1 MiB limit, five
  inert format tags, and a resumable in-memory quarantine receiver. Output is byte-identical to the upstream
  `transport.py` for seven vectors (executed from the pinned checkout, not copied).
- `chromaneural-mcp-limits` (profile only, PENDING), `roboforge-mcp` (G15), `chromaplex-data-tags` (CPL/CPA
  are inert tagged data), `prisme-symbols` (structure only: 4x7 symbols, UV control, no byte codec; DISCREPANCY).
- Each adapter declares least-authority capabilities and limits; the registry validator rejects execution,
  approval, listening or upstream-modification authority and unversioned entries.
- `kernel/hmac_sha256.{h,c}` (RFC 4231 vectors) supports CNRB.
- Tests: `tests/gates/G16_compat_test.c`, `G16_test.py`, `scripts/test-compat-host.sh` (plain and ASan/UBSan),
  vectors in `tests/gates/fixtures/chromaneural/` regenerated by `scripts/g16_generate_vectors.py`.

## Not implemented

COMPATIBILITY_PENDING (inert, no authority):
- `chromaneural-node-admission`: no Ed25519 signature/TLS verification, no node admission, task exchange,
  capability-aware assignment or resource accounting; upstream marks these NOT VERIFIED/disabled.
- `chromaneural-mcp-limits`: ChromaNeural tool-definition fingerprint canonicalization and live approval.
- `chromaplex-compiler`: needs a Python runtime (G17) and independent verification.
- PRISME byte-level codec and optical behaviour: unverifiable from public sources and licence-restricted;
  RGB output is never treated as UV emission. Robotics APIs beyond G15 and local network transport are not part of this gate.
- No upstream project was modified. ChromaNeural authentication, accounting, WorkQueue and authorization are untouched.
- Hardware: HARDWARE_NOT_VERIFIED.
